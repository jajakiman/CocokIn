# Domain Documentation

CocokIn uses a single domain context.

- Canonical vocabulary: `CONTEXT.md`
- Product requirements: `PRD.md`
- Hard-to-reverse architecture decisions: `docs/adr/`
- Business policy: `docs/BUSINESS_RULES.md`
- State contracts: `docs/DATA_STATE_MODEL.md`

Update `CONTEXT.md` only for domain language, not implementation details. Record an ADR only when a decision is expensive to reverse, surprising without context, and the result of a genuine trade-off.
